# Deployment Guide

This project can be deployed as a static site on **Vercel** or **Render**. The frontend is a React app that builds into static files; the backend (if used) can be hosted separately, but the current version works entirely client‑side.

---

## Vercel
1. **Push to GitHub** – Ensure the repository (including `frontend/`, `vercel.json`, and `host.md`) is committed and pushed.
2. **Import Project** – In the Vercel dashboard, click *New Project* → *Import Git Repository* and select your repo.
3. **Project Settings**:
   - **Root Directory**: `frontend`
   - **Build Command**: `npm install && npm run build`
   - **Output Directory**: `frontend/build`
4. **SPA Routing** – The `vercel.json` file contains a rewrite rule that redirects all routes to `index.html`.
5. **Deploy** – Click *Deploy*. Once the build succeeds, Vercel provides a URL like `your-project.vercel.app`.
6. **Environment Variables** (if needed): none for the client‑side version.

---

## Render (Frontend Static Site)
1. **Create a Static Site** – In Render, click *New* → *Static Site*.
2. **Connect Repository** – Link the same GitHub repo.
3. **Root Directory**: `frontend`
4. **Build Command**: `npm install && npm run build`
5. **Publish Directory**: `frontend/build`
6. **Deployment Configuration** – The `render.yaml` file in the repo defines the build and routing settings; Render will read it automatically.
7. **Deploy** – Render will build and serve the site at a URL like `your-project.onrender.com`.

---

## Render (Backend Web Service)
If you wish to deploy the Python/Django backend service:
1. **Create a Web Service** – In Render, click *New* → *Web Service*.
2. **Connect Repository** – Link the same GitHub repo.
3. **Language** – Select **Python**.
4. **Build Command** – Set to `pip install -r requirements.txt && python backend/manage.py collectstatic --noinput`.
5. **Start Command** – Set to `gunicorn --chdir backend backend.wsgi:application`.
6. **Environment Variables**:
   - `DEBUG`: `False` (disables Django debug mode for production security)
   - `SECRET_KEY`: A long, random, secure key (e.g. `your-random-32-char-key`)
   - `ALLOWED_HOSTS`: Set to your backend domain (e.g., `your-backend.onrender.com`) or `*`.
   - `PYTHON_VERSION`: `3.10.2` (or matches your system's python version).


---

## Important Notes
- Both platforms serve the static files generated by `npm run build`. The folder‑picker for music files works entirely in the browser, so no server‑side handling of user files is required.
- Ensure the **`.gitignore`** excludes `node_modules/` and any local environment files, but **includes** the `vercel.json` and `render.yaml` so they are deployed.
- After deployment, test the app by opening the live URL and using the *Select Music Folder* button to grant folder access.

---

## Troubleshooting
- **Build Failures** – Verify that the Node version on the platform matches the version used locally (e.g., Node 18). You can set the Node version via an `.nvmrc` file.
- **Folder Access** – The File System Access API works only in secure contexts (HTTPS). Both Vercel and Render serve over HTTPS, so the picker will function.
- **CORS Issues** – No external API calls are made; if you add a backend later, configure appropriate CORS headers.
